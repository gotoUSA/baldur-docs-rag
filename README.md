# baldur-docs-rag

Baldur(Python 외부 API 장애 대응 라이브러리) 공개 문서를 대상으로 한 RAG입니다. 질문하면 문서 근거를 붙여 답을 생성하고, 문서에 근거가 없으면 거절을 돌려줍니다. RAG와 도구 호출을 직접 만들고 숫자로 평가해 보려고 만든 학습 프로젝트이며, 제품이 아닙니다.

- 역할: 무엇을 만들고 어떻게 측정할지는 직접 정했습니다. 코드 작성, 분석, 실행, 측정은 Claude Code(AI 코딩 도구)로 했습니다. 결정마다 AI 제안인지 직접 선택인지는 [`eval/RECORD.md`](eval/RECORD.md)에 표시했습니다.
- 실제 API로 돌려 본 모델: `gemini-embedding-2`(768차원), `gemini-3.6-flash`.

## 요약

- Baldur 문서 117개를 청크 1,083개로 나눠 PostgreSQL(pgvector)에 임베딩해 두고, 질문하면 가까운 청크 5개를 근거로 Gemini가 답과 출처를 돌려줍니다. 근거가 없으면 거절합니다.
- 모델 응답을 그대로 쓰지 않습니다. 인용 번호가 실제로 보낸 청크인지, 재검색 도구 호출의 이름·인자·횟수가 맞는지 코드가 검사하고, 맞지 않으면 답을 보여 주지 않고 실패로 끝냅니다.
- 질문 세트를 만들어 측정했습니다. 문서를 보지 않고 만든 질문 25개에서 답이 담긴 청크가 상위 5개에 든 것은 15개였습니다. 놓친 10개 중 6개는 거절했고, 4개는 다른 청크를 근거로 답했는데 AI 채점에서 인용 문단에 충실하다고 판정됐습니다.
- 키워드 검색 섞기와 리랭커 두 개는 적중을 떨어뜨렸습니다. 질의 재작성(HyDE)은 따로 봉인해 둔 질문 18개에서 적중을 10개에서 12개로 올렸지만, 이 크기로는 우연과 구별되지 않습니다. 측정 설정과 판정 기준은 결과를 보기 전에 [`eval/RECORD.md`](eval/RECORD.md)에 적었습니다.

## 하는 일

| 명령 | 하는 일 |
|---|---|
| `ingest` | Baldur 저장소의 git 커밋 하나에서 문서를 읽어 제목 단위로 나누고(2,000자가 넘으면 빈 줄에서 다시 나눔), 임베딩해 PostgreSQL(pgvector)에 저장합니다. 할당량에 걸려 멈추면 저장된 묶음부터 이어서 합니다 |
| `search "질문"` | 질문과 가장 가까운 청크 5개를 점수, 경로, 제목, 문서 커밋과 함께 보여 줍니다 |
| `ask "질문"` | 청크 5개를 넣어 Gemini로 답을 생성하고 출처를 붙입니다. 모델 응답에 `search_docs` 도구 호출(재검색)이 한 번 올 수 있고, 코드가 호출 내용을 검사한 뒤에만 실행합니다 |
| `evaluate` | 고정 질문 세트로 검색 적중률, 출처 일치, 거절률을 측정하고 결과를 파일로 남깁니다. 도구 호출은 쓰지 않습니다 |

질문 하나의 흐름(`ask`):

1. 코드가 질문을 `gemini-embedding-2`로 벡터(숫자 768개)로 바꿉니다.
2. PostgreSQL이 청크 1,083개 전부와 코사인 거리를 계산해 가까운 5개를 돌려줍니다. 인덱스를 쓰지 않으므로 근사가 아닌 정확한 순위입니다.
3. 코드가 청크에 `[1]`~`[5]` 번호를 붙여 질문과 함께 Gemini에 보냅니다.
4. Gemini가 JSON으로 답, 인용 번호, 답 가능 여부를 돌려줍니다. 응답이 재검색 도구 호출이면 코드가 도구 이름, 인자, 길이, 횟수를 검사해 통과한 경우에만 검색하고, 결과를 넣어 Gemini를 다시 호출합니다.
5. 코드가 인용 번호가 실제로 보낸 청크인지 검사한 뒤, 번호를 파일 경로와 문서 커밋으로 바꿔 보여 줍니다. 검사에 걸리면 답을 보여 주지 않고 실패로 끝냅니다.

검색이나 모델 호출이 실패하면 답을 만들지 않고 실패로 끝냅니다.

### 결과에서 알게 된 것

1. 질문을 만든 방법에 따라 검색 적중이 달랐습니다. 상위 5개 적중은 1차 18/18, 2차 15/25이고, 95% 구간(82~100%, 41~77%)도 겹치지 않습니다. 1차 질문이 문서와 표현이 비슷해서 검색에 유리했다고 의심해 2차를 만들었습니다. 나중에 질문 단어가 정답 청크에도 있는 비율을 영어 질문으로 측정해 보니 1차 평균 0.57, 2차 0.49로 차이가 작았고, 한국어 질문은 정답 청크와 겹치는 단어가 거의 없는데도 1차에서 10개 모두 검색됐습니다. 단어 겹침으로는 두 세트의 차이를 설명하지 못했고, 차이의 원인은 확인하지 못했습니다.
2. 검색이 정답 청크를 놓친 질문에서는 주로 거절이 나왔습니다. 2차 답 있는 질문 25개 중 정답 청크가 상위 5개에 든 15개는 모두 답이 나왔습니다. 들지 못한 10개 중 6개는 거절, 4개는 다른 청크를 근거로 한 답이었고, 그 4개도 AI 채점에서 인용 문단과 내용이 맞는다고 판정됐습니다. 예를 들어 "특정 엔드포인트의 automatic recovery를 끌 수 있나"는 이름이 비슷한 다른 기능(Canary Recovery) 문서만 검색돼 거절됐습니다. 틀린 답은 없었고, 문서에 답이 있는데 거절한 질문이 6개였습니다.
3. 거절 6개는 모두 검색이 정답 청크를 놓친 질문이었습니다. 그래서 고칠 곳은 답 생성보다 검색으로 봤습니다. 놓친 10개에서 정답 청크의 순위를 50위까지 찾아보니 7개는 6~50위, 3개는 50위 밖이었습니다. 6~50위의 7개는 순위를 다시 매기는 방법(리랭커)으로 고칠 수 있다고 봤지만, 시험한 리랭커 두 개는 나아지지 않았습니다(아래 표). 50위 밖 3개는 질문과 문서가 같은 내용을 다른 말로 쓰고 있었습니다(AI 분석). 예를 들어 질문은 "서비스별 정책"을 물었고, 문서는 "호출마다 키워드 인자로" 정한다고 적었습니다.
4. 출처 일치 14/19는 답 5개가 틀렸다는 뜻이 아닙니다. 출처 일치는 인용한 청크 중에 미리 정한 정답 청크가 하나라도 있는지 셉니다. 일치하지 않은 5개도 AI 채점에서 인용 문단과 내용이 맞는다고 판정됐습니다. 정답 청크는 Claude 세션 2개가 둘 다 고른 것만 썼는데, 5개 중 3개는 한쪽 세션만 고른 청크를 인용했습니다. 정답을 좁게 정한 규칙 때문에 숫자가 낮게 나온 부분이 있습니다.

## 질의 재작성 (방향 확인)

검색 전에 `gemini-3.6-flash`로 질문을 다시 쓰는 방법을 측정 스크립트(`eval/results/rewrite/measure_rewrite.py`)로 시험했습니다. `search`, `ask`, `evaluate` 코드에는 넣지 않았습니다. 설정, 후보를 고르는 규칙, 3차 판정 기준은 결과를 보기 전에 [`eval/RECORD.md`](eval/RECORD.md)에 적었습니다.

1. 질문마다 Flash를 한 번 호출해 JSON으로 두 가지를 받습니다. 문서에 나올 법한 말로 쓴 짧은 영어 검색어, 그리고 질문에 답하는 문서 문단처럼 쓴 짧은 글(HyDE)입니다.
2. 원래 질문과 재작성 결과를 각각 임베딩해 검색합니다. "교체"는 재작성 결과로 찾은 5개만 쓰고, "합치기"는 원래 질문의 결과와 1위부터 번갈아 넣고 중복을 뺀 5개를 씁니다.
3. 상위 5개에 정답 청크가 있는지 셉니다.

| 후보 | 1차 적중 | 2차 적중 |
|---|---|---|
| 벡터 검색만 (현재) | 18/18 | 15/25 |
| 검색어로 교체 | 16/18 | 14/25 |
| 검색어와 합치기 | 18/18 | 16/25 |
| HyDE로 교체 | 16/18 | 20/25 |
| HyDE와 합치기 | 18/18 | 18/25 |

- 미리 정한 규칙(1차 18/18을 유지한 후보 중 2차가 가장 높은 것)으로 "HyDE와 합치기"를 골랐습니다. 2차는 놓친 원인을 진단할 때 이미 본 세트라서, 18/25는 후보를 고르는 데 쓴 값이고 개선의 증거가 아닙니다.
- 따로 봉인해 둔 3차 세트(답 있음 18개, 관련 있지만 답 없음 7개, 무관 4개)로 벡터 검색만과 한 번 비교했습니다(2026-11-15~17).

| 3차 | 벡터 검색만 | HyDE와 합치기 |
|---|---|---|
| 상위 5개 적중 (답 있음 18개) | 10/18 | 12/18 |
| 답 없는 질문 11개 중 답한 수 | 0 | 0 |

- HyDE와 합치기에서만 맞힌 질문이 2개, 벡터 검색에서만 맞힌 질문이 0개입니다. 미리 정한 기준(순증 2 이상)을 경계값으로 넘었습니다. 답 없는 질문 11개는 둘 다 모두 거절했습니다.
- 18문항으로는 방향만 확인할 수 있습니다. 측정 전에 계산한 검정력으로는 효과가 없어도 순증 2 이상이 나올 확률이 5~19%입니다. 판정에 쓰지 않은 참고 값인 짝지은 무작위화 검정의 한쪽 p값은 0.25입니다. 이 결과로는 "개선과 같은 방향"까지만 말할 수 있습니다.
- 3차는 결과를 보고 방법을 고치지 않도록, 질문 내용을 보지 않고 문항 번호와 적중 여부만 센 세트입니다. 그래서 3차의 벡터 적중 10/18이 1·2차보다 낮은 이유는 진단하지 않았습니다.

## 확인하지 못한 것 (미룸)

적중이 낮은 원인이 벡터 상위 5개 방식에 있는지, 검색해서 붙이는 방식(RAG) 자체에 있는지는 확인하지 않았습니다. 확인 순서는 정해 두었습니다.

1. 2·3차 59문항으로 세 방식을 답 단위 지표로 비교해 하나를 고릅니다. 벡터 상위 5개, 문서 전체를 컨텍스트에 넣기, 에이전트 검색(모델 응답의 도구 호출로 파일 검색과 읽기를 여러 번 실행)입니다.
2. 엣지 케이스 유형(잘못된 전제, 끼워 넣은 지시, 모호한 질문, 일부만 답 있음)을 넣은 4차 세트를 새로 봉인하고, 고른 방식과 벡터 상위 5개를 한 번 비교합니다.

문서 전체는 254,094토큰입니다(2026-11-17, `gemini-3.6-flash`의 countTokens로 측정). 무료 등급의 분당 한도 250K를 넘어 유료 등급이 필요해서 이 확인은 미뤘습니다(직접 결정).

## 한계

- 질문이 적습니다. 답 없는 질문은 1차 12개, 2차 5개라서 거절 숫자의 구간이 넓습니다.
- 거절한 이유가 맞았는지는 측정하지 않았습니다.
- 답변 채점은 AI로 했습니다. 답한 37개 중 15개를 무작위로 뽑아 직접 채점했고, AI 채점과 15/15 일치했습니다(95% 구간 80~100%). 그 15개에는 AI 채점이 틀림으로 판정한 답이 없어서, 틀린 답을 AI 채점도 틀림으로 판정하는지는 확인하지 못했습니다.
- 질의 재작성은 측정 스크립트로만 시험했고 `ask`에는 넣지 않았습니다. 넣으면 질문마다 Flash 호출이 한 번 더 듭니다.
- 도구 호출(재검색)이 답 품질에 주는 효과는 측정하지 않았습니다. 실제 API로 질문 두 개를 한 번씩 돌려 본 관찰만 있습니다.

## 실행

필요한 것: Python 3.12 이상, Docker, Gemini API 키, 이 저장소 옆에 클론한 Baldur 저장소(`../baldur`).

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"   # Windows. macOS/Linux는 .venv/bin/python
docker compose up -d --wait                        # PostgreSQL + pgvector, 127.0.0.1:5433
```

`.env`에 키를 적습니다. 설정은 `.env`에서만 읽고 OS 환경 변수는 무시합니다(`config.py`).

```
GEMINI_API_KEY=...
SOURCE_REF=20a2f7f3ecf44d2cec4721827a9bb9847748dcb0   # 위 결과와 같은 문서 커밋
```

```bash
python -m baldur_docs_rag ingest
python -m baldur_docs_rag search "How do I configure the circuit breaker?"
python -m baldur_docs_rag ask "How do I configure the circuit breaker?"
python -m baldur_docs_rag evaluate                  # 세트는 .env의 EVAL_QUESTIONS_PATH로 고름
```

무료 등급에서는 첫 `ingest`가 이틀 걸립니다. 청크 1,083개가 임베딩 하루 한도 1,000개를 넘기 때문입니다.

테스트는 `tests/unit/`, `tests/integration/`에 있습니다. PostgreSQL이나 실제 Gemini가 필요한 테스트는 marker(`postgres`, `gemini`)로 표시해 두었고, 없으면 건너뛴 사실이 결과에 표시됩니다.

```bash
.venv/Scripts/python -m pytest
```
