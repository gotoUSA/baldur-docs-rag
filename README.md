# baldur-docs-rag

Baldur(Python 외부 API 장애 대응 라이브러리)의 공개 문서에 질문하면, 문서 근거를 붙여 답하고 문서에 없으면 모른다고 답하는 RAG입니다. RAG와 도구 호출을 직접 만들어 보고 숫자로 평가하는 것이 목적인 학습 프로젝트이며, 제품이 아닙니다.

- 역할: 무엇을 만들고 어떻게 잴지는 사용자가 판단했습니다. 코드 작성, 실행, 측정, 분석은 AI 에이전트(Claude Code)가 했습니다. 결정마다 누가 했는지는 [`docs/PROJECT_HISTORY.md`](docs/PROJECT_HISTORY.md) 5절에 있습니다.
- 실제 API로 돌려 본 모델: `gemini-embedding-2`(768차원), `gemini-3.6-flash`.

## 하는 일

| 명령 | 하는 일 |
|---|---|
| `ingest` | Baldur 저장소의 git 커밋 하나에서 문서를 읽어 제목 단위로 나누고(2,000자가 넘으면 빈 줄에서 다시 나눔), 임베딩해 PostgreSQL(pgvector)에 저장합니다. 할당량에 걸려 멈추면 저장된 묶음부터 이어서 합니다 |
| `search "질문"` | 질문과 가장 가까운 청크 5개를 점수, 경로, 제목, 문서 커밋과 함께 보여 줍니다 |
| `ask "질문"` | 청크 5개를 근거로 Gemini가 답하고 출처를 붙입니다. 근거가 부족하면 모델이 `search_docs` 도구로 재검색을 한 번 요청할 수 있고, 코드가 요청을 검사한 뒤에만 실행합니다 |
| `evaluate` | 고정 질문 세트로 검색 적중률, 출처 일치, 거절률을 재고 결과를 파일로 남깁니다. 도구 호출은 쓰지 않습니다 |

질문 하나의 흐름(`ask`):

1. 코드가 질문을 `gemini-embedding-2`로 벡터(숫자 768개)로 바꿉니다.
2. PostgreSQL이 청크 1,083개 전부와 코사인 거리를 계산해 가까운 5개를 돌려줍니다. 인덱스를 쓰지 않으므로 근사가 아닌 정확한 순위입니다.
3. 코드가 청크에 `[1]`~`[5]` 번호를 붙여 질문과 함께 Gemini에 보냅니다.
4. Gemini가 JSON으로 답, 인용 번호, 답할 수 있는지 여부를 돌려줍니다. 재검색을 요청했다면 코드가 도구 이름, 인자, 길이, 횟수를 검사해 통과한 경우에만 검색하고 결과를 돌려준 뒤 다시 묻습니다.
5. 코드가 인용 번호가 실제로 보낸 청크인지 검사한 뒤, 번호를 파일 경로와 문서 커밋으로 바꿔 보여 줍니다. 검사에 걸리면 답을 보여 주지 않고 실패로 끝냅니다.

검색이나 모델 호출이 실패하면 답을 지어내지 않고 실패를 알립니다.

## 결과

조건: 문서 커밋 `20a2f7f3ecf44d2cec4721827a9bb9847748dcb0`(117개 파일, 청크 1,083개), 모델 `gemini-embedding-2`·`gemini-3.6-flash`, 상위 5개 검색. 측정일은 1차 2026-11-05~07, 2차 2026-11-07~09입니다. 괄호 안은 95% Wilson 구간입니다.

| 지표 | 1차 (질문 30개) | 2차 (질문 30개) |
|---|---|---|
| 질문을 쓴 방식 | AI가 무작위로 뽑은 청크를 보고 초안, 사용자가 수정 없이 승인 | 문서를 보지 않은 다른 모델(ChatGPT 웹 채팅)이 작성 |
| 구성 (답 있음 / 관련 있지만 답 없음 / 무관) | 18 / 8 / 4 | 25 / 1 / 4 |
| 검색 적중 (상위 5개에 정답 청크) | 18/18 (82~100%) | **15/25 (41~77%)** |
| 1위에 정답 청크 | 12/18 (44~84%) | 9/25 (20~55%) |
| 출처 일치 | 18/18 (82~100%) | 14/19 (51~88%) |
| 답이 있는데 거절 | 0/18 (0~18%) | **6/25 (11~43%)** |
| 답변이 인용 문단에 충실 (AI 채점) | 17/18 (74~99%) | 19/19 (83~100%) |
| 거절 (관련 있지만 답 없음) | 8/8 (68~100%) | 1/1 (21~100%) |
| 거절 (무관) | 4/4 (51~100%) | 4/4 (51~100%) |
| 형식이 틀려 버린 응답 | 0 | 0 |

- 2차의 정답 청크는 서로 모르는 Claude 세션 2개가 붙였고, 둘이 함께 고른 청크(교집합)만 썼습니다.
- 답변 채점은 사람이 아니라 서로 모르는 Claude 세션 2개(`claude-opus-5-5`)가 했습니다. 본 것은 "답이 인용 문단에 충실한가"이고, 문서 내용이 사실인지는 보지 않았습니다. 판정이 갈리면 틀림으로 세기로 미리 정했습니다(실제로는 1차 18/18, 2차 19/19 일치). 같은 모델의 일치이므로 판정이 맞다는 증거는 아닙니다.

### 결과에서 알게 된 것

1. **1차 만점은 질문이 문서를 닮아서였을 가능성이 큽니다.** 문서를 보지 않고 쓴 2차에서 검색 적중이 15/25로 떨어졌습니다. 두 세트는 질문이 달라 같은 질문에서 비교한 결과는 아닙니다.
2. **검색이 놓친 질문은 대부분 거절로 끝났습니다.** 2차에서 검색이 정답 청크를 놓친 질문 10개 중 6개는 거절했고, 4개는 다른 청크로 답했습니다. 그 4개도 AI 채점에서 인용 문단에 충실했습니다. 검색이 맞힌 15개에서는 거절이 없었습니다.
3. **약점은 검색입니다.** 놓친 정답 청크의 순위를 상위 50개까지 확인해 보니, 6~50위에 있던 것이 7개, 50위 밖이 3개였습니다. 50위 밖 3개는 문서가 질문과 다른 말로 쓰여 있었습니다(AI 분석).
4. **출처 일치 14/19는 답이 틀렸다는 뜻이 아닙니다.** 일치하지 않은 5개도 AI 채점에서 인용 문단에 충실했습니다. 정답 청크를 교집합으로 좁힌 규칙 때문에 낮게 나온 부분이 있습니다.

## 한계

- 질문이 적습니다. 답 없는 질문은 1차 12개, 2차 5개뿐이라 거절 숫자의 구간이 넓습니다.
- 거절한 이유가 맞았는지는 재지 않았습니다.
- 답변 채점은 AI가 했습니다. 답한 37개 중 15개를 무작위로 뽑아 작성자가 따로 채점했고, 15/15 일치했습니다(95% 구간 80~100%). 다만 그 15개에 AI가 틀림으로 본 답이 없어서, AI가 틀린 답을 알아보는지는 확인하지 못했습니다.
- 도구 호출(재검색)이 답 품질에 주는 효과는 재지 않았습니다. 실제 API로 질문 두 개를 각각 한 번씩 돌려 본 관찰만 있습니다.
- 무료 등급 한도(Flash 하루 20회) 때문에 평가를 여러 날에 나눠 돌렸습니다.

## 실행

필요한 것: Python 3.12 이상, Docker, Gemini API 키, 이 저장소 옆에 클론한 Baldur 저장소(`../baldur`).

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"   # Windows. macOS/Linux는 .venv/bin/python
docker compose up -d --wait                        # PostgreSQL + pgvector, 127.0.0.1:5433
```

`.env`에 키를 적습니다. 설정은 `.env`에서만 읽고 OS 환경 변수는 무시합니다(`config.py`).

```
GEMINI_API_KEY=...
SOURCE_REF=20a2f7f3ecf44d2cec4721827a9bb9847748dcb0   # 위 결과와 같은 문서 커밋
```

```bash
python -m baldur_docs_rag ingest
python -m baldur_docs_rag search "How do I configure the circuit breaker?"
python -m baldur_docs_rag ask "How do I configure the circuit breaker?"
python -m baldur_docs_rag evaluate                  # 세트는 .env의 EVAL_QUESTIONS_PATH로 고름
```

무료 등급에서는 첫 `ingest`가 이틀 걸립니다. 청크 1,083개가 임베딩 하루 한도 1,000개를 넘기 때문입니다.

테스트는 `tests/unit/`, `tests/integration/`에 있습니다. PostgreSQL이나 실제 Gemini가 필요한 테스트는 marker(`postgres`, `gemini`)로 표시해 두었고, 없으면 건너뛴 사실이 결과에 표시됩니다.

```bash
.venv/Scripts/python -m pytest
```
